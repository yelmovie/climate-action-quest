# 기후 미래 작전실 · TRD

작성: 2026-10-21 · 대상: PRD의 완주 가능한 로컬 웹 MVP

## 1. 기술 결정

실행 소스가 없던 폴더에 브라우저 기본 기능 중심의 Vanilla JavaScript ES modules 앱을 구축한다. 지도는 픽셀 배경·배치 좌표·이동 상태로 2.5D RPG 경험을 제공하고, 시설은 DOM·SVG·2D 이미지로 렌더한다. 외부 프레임워크·런타임 CDN·3D 라이브러리는 요구하지 않는다. Jua OFL 1.1 한글·라틴 웹폰트는 앱 내부에 동봉한다. 서버는 정적 파일만 제공하며 학습 기록 API는 없다.

원본 `references/`는 수정하지 않는다. 배포 이미지에는 `assets/`의 최적화 WebP를 사용한다. 제공 이미지의 WebP 변환·NPC 포트레이트 셀 추출은 `python scripts/prepare-assets.py`로 재현하며, 변환 정보는 `docs/reference-review/prepared-assets.json`에 기록한다. 추가 지도·캐릭터의 생성 이력은 별도 기록한다.

## 2. 화면·렌더 책임

| 계층 | 책임 | 경계 |
|---|---|---|
| 앱 셸 | 홈, 공통 HUD, 설정·스토리·보상 dialog, 라우팅 | 활동 DOM 내부의 정답 로직을 관리하지 않음 |
| 지도 | 월드 좌표, 이동·카메라, 시설 입구, 학생과 동행 NPC | 완료 여부는 저장 상태에서 읽고 별도 완료 복제본을 만들지 않음 |
| 활동 | 관측·연결·예측·비교·배치·시험 및 활동별 진행 복원 | 글로벌 라우팅·관리자 접근 권한을 직접 변경하지 않음 |
| 상태 | 로컬 저장, 검증·기본값·완료·해금 규칙 | 저장 문자열을 HTML로 주입하지 않음 |
| 시각 시스템 | 타이포·색·버튼·모달·상태·반응형 | 과학 수치·학습 규칙을 CSS에 숨기지 않음 |

활동 진입 계약:

```js
mountActivity(host, {
  index,        // 0..9
  state,        // records, completed, adminUnlocked 등
  save,         // 현재 상태를 저장
  complete,     // 학습 조건을 충족하면 요약과 함께 호출
  icon, asset, announce
});             // 화면을 떠날 때 실행할 cleanup 함수 반환
```

콘텐츠는 `src/activity-data.js`, 활동은 `src/activities.js`, 공통 SVG는 `src/icons.js`, 시각 토큰은 `src/styles.css`로 분리한다. 실제 셸·저장·지도 모듈명은 구현을 기준으로 한다.

## 3. 상태와 저장 계약

| 데이터 | 의미 | 안전 조건 |
|---|---|---|
| `completed` | 실제 수행을 마친 활동 index 목록 | 중복 제거, 0~9 정수만 허용 |
| `records` | 활동 index별 작업·비교·실험·설계 기록 | JSON 직렬화 가능, 없는 기록은 기본값 제공 |
| `adminUnlocked` | 모든 장·활동 접근 허용 | 완료 배열·학생 보상을 채우지 않음 |
| 현재 화면 | 홈/지도/시설/활동 및 index | 알 수 없는 경로는 홈 또는 지도로 복구 |
| 음향 환경 | 배경음·효과음·배경음 크기 | 기록 초기화와 분리 보존 |

기록은 관측 추가, 선택, 실험 실행, 시설 배치, 단계 완료 후 저장한다. 새로고침 시 같은 단계와 이미 선택한 항목을 복원한다. 로컬 저장소가 차단되거나 용량이 부족하면 화면에 저장 불가를 알리고 현재 세션의 탐구는 계속한다. 손상된 저장 때문에 앱 전체가 흰 화면으로 중단되지 않게 기본 상태로 복구한다.

사용자 입력을 받더라도 `textContent`로 표시한다. `innerHTML` 템플릿에는 개발자가 정의한 문자열·검증된 숫자·열거형만 사용한다. 이름·연락처·학번은 수집하지 않는다. 초기화는 확인 dialog에서만 수행하고, 취소에 첫 포커스를 둔다.

## 4. 학습 데이터 연속성

1. 활동01의 수집 기록을 활동02의 판단 자료로 사용한다.
2. 활동03에서 확인한 인간 활동을 활동04의 연결망으로 이어 쓴다.
3. 활동05의 예상·수위·결과를 활동06의 영향 연쇄와 연결한다.
4. 활동07의 실제 선택을 활동08의 기준 선택으로 사용한다. 비교 시 나머지 조건을 고정한다.
5. 활동09의 실제 배치를 활동10에서 읽는다. 같은 기상 조건과 계산식으로 수정 전후를 시험한다.

관리자 진입에 선행 기록이 없으면 예시임을 표시하는 별도 입력을 제공한다. 예시를 실제 수집 기록인 것처럼 저장하거나 예시 열람만으로 학생 수행 완료를 기록하지 않는다. 최종 보고는 실제 완료·기록에서 생성한다.

## 5. 2D 모형 계산 규칙

- 수위 단계·구역 높이·영향 단계는 가상 교육 모형의 상대값이다. 실제 m·℃·mm·미래 연도 피해율로 포장하지 않는다.
- 활동05: 학생 예상 구역과 선택한 수위의 실제 모형 영향 구역을 각각 보존해 차이를 보여준다. 예상이 빗나가도 재시험할 수 있다.
- 생활 지표: 기후 부담·생활 만족·사용 자원은 선택지를 비교하는 상대 지표다. 한 행동이 당장 실제 홍수·폭염 위험을 낮춘다고 계산하지 않는다.
- 도시 설계: 구역별 위험과 시설 효과를 데이터로 정의한다. 비용은 배치마다 계산하고 예산 초과 배치를 거절한다. 교체 시 종전 시설 비용을 되돌린다.
- 스트레스 테스트: 폭염·많은 비 각각의 조건을 고정하고 원 설계와 수정 설계에 동일 함수를 적용한다. 다시 설계한 결과가 개선되거나 이미 충분한 설계를 확인해야 최종 단계가 열린다.
- 위 계산은 DOM과 분리한 순수 함수로 검사한다. 제한·단조성·예산·원본 기록 불변·동일 입력 동일 결과가 핵심 테스트다.

## 6. 지도 이동과 시설 접근

그림 좌표를 월드 기준으로 쓰고 화면은 cover에 맞춘 뒤 카메라만 이동한다. 학생과 보조 NPC의 발 위치를 기준으로 접지한다. 선택 이름표는 DOM 버튼으로 제공해 캔버스 클릭만 의존하지 않는다.

방향키·WASD는 `event.code` 기준으로 처리하고 대각선 이동은 속도를 정규화한다. 길·건물 탭도 같은 이동 상태를 사용한다. 자동 이동 중 수동 입력이 들어오면 자동 경로를 취소한다. 지도 밖·물·건물 벽을 걷지 않게 허용 경로를 검증하고 시설 입구까지 연결되었는지 테스트한다.

시설 입구 진입은 경계에 들어오는 순간에 한 번만 처리한다. 활동에서 돌아왔을 때 입구에 서 있다는 이유로 재입장하지 않는다. 관리자 해금은 접근만 허용하며 기본 시설 순서는 실제 완료 기록에서 계산한다.

dialog가 열리거나 탭이 숨겨지거나 화면을 떠나면 입력·프레임 루프를 정리한다. 프레임 시간차에 상한을 두어 복귀 후 순간이동을 막는다. 동작 줄이기 환경에서는 과한 걷기·축하 모션을 줄이고 최종 상태를 표시한다.

## 7. 공통 UI·접근성

공통 HUD는 왼쪽 위 홈·이전, 오른쪽 위 전체 소리·설정 네 SVG 버튼이다. 별도의 상단·하단 바는 없다. 화면 전체 배경 위에 필요한 패널만 얹는다. 지도의 진행은 복구된 건물 불빛과 이름표로 보여준다.

제목·본문·버튼 크기는 `clamp()`와 높이 미디어 쿼리로 조정한다. 한국어는 `word-break: keep-all`을 적용한다. 터치 대상은 48px 이상이다. 정오답은 색과 함께 문구·아이콘으로 표시한다. range에는 label과 현재 값을 제공한다.

설정은 `<dialog>.showModal()`과 접힘 `<details>`를 사용한다. Esc·닫기 후 여는 버튼으로 포커스를 돌린다. 스크린리더 안내는 polite live region으로 제공한다. 소리 설정은 별도 저장하며 BGM 크기 슬라이더는 BGM이 꺼지면 비활성이다. 음향 컨텍스트는 사용자 입력 후에만 시작하고 한 관리자가 재생·중지를 담당한다.

## 8. 로딩·오프라인·배포

첫 화면은 홈 배경과 필수 앱 셸만 먼저 로딩한다. 시설 배경은 필요한 화면에서 불러온다. 캐시 준비 완료 전에는 오프라인 완주를 보장하지 않는다. 서비스 워커의 사전 캐시에는 실제 배포 파일만 넣고 갱신된 버전의 캐시만 정리한다.

외부 네트워크 라이브러리나 폰트 CDN 요청을 만들지 않는다. 로컬 Jua WOFF2 두 파일과 OFL 원문은 정적 배포·오프라인 캐시에 함께 포함한다. 배포는 정적 파일 호스팅이며 딥링크나 하위 경로는 실제 호스팅 설정에서 확인한다. 설치·생성 자료는 D: 프로젝트 위치에 둔다. 개발용 이미지 원본·검수 스크린샷을 학생 배포본에 무조건 포함하지 않는다.

테스트 실행·측정 수치·남는 조건은 `docs/reviews/`의 실제 검수 보고서를 따른다. 이 문서의 목표를 측정 완료 결과로 취급하지 않는다.
