# 16번 기후 미래 작전실 · 첫 화면 로딩 개선

첫 화면과 인트로 세 장면은 유지했다. 지도에 들어가면 지도 코드와 그림을 함께 요청한다. 활동에 들어갈 때 공통 활동 코드와 해당 시설의 시각 스타일을 받는다. 도시 운영 미션·개념 영상·인증서 내보내기 코드는 각 기능을 열 때 받는다. 인트로에 쓰던 마을 그림은 이야기 장면에서 그대로 보인다.

지도 코드 실패 시 **다시 열기**로 지도 주소를 새로고침한다. 지도 그림 실패 시에는 지도 자료만 다시 요청한다. **첫 활동 시작**은 지도 없이 첫 관측을 열고, 진행 중인 기록이 있으면 현재 이어 할 수 있는 활동을 안내한다. 대기 상한은 지도 코드 10초, 지도 자료 20초다.

서비스워커는 첫 접속에 전체 자료를 내려받던 대신, 요청한 자료를 캐시에 저장한다. 전체 오프라인 이용은 **설정 → 오프라인 자료 받기**에서 준비할 수 있다.

| 지표 | 로컬 전 → 후 | 느린 환경 전 → 후 |
| --- | ---: | ---: |
| 접속 → 시작 버튼 조작 가능 | 48 → 43 ms | 1,030 → 643 ms |
| 첫 내용 표시(FCP, 초기 안내 포함) | 40 → 44 ms | 404 → 344 ms |
| 첫 화면 주요 콘텐츠 표시(LCP) | 72 → 68 ms | 1,056 → 664 ms |
| 인트로 종료 → 지도 준비 | 60 → 111 ms | 2,066 → 2,346 ms |
| 시설에서 첫 활동 선택 → 조작 가능 | 31 → 41 ms | 55 → 324 ms |

같은 Mac의 로컬 서버에서 변경 직전과 변경 후의 정적 배포 빌드를 비교했다. Chrome 1280×800, 동작 줄이기, 캐시와 서비스워커를 끈 새 브라우저에서 조건별·버전별 5회 교차 실행의 중앙값이다. 느린 환경은 다운로드 10 Mbps, 지연 40 ms, CPU 4배 감속을 적용했다. 첫 화면의 JS·CSS 요청은 46 → 23개, 압축 전 JS는 254 → 77 kB, CSS는 184 → 131 kB였다. 지도·활동·미션 모듈은 첫 화면에서 내려오지 않았다. 서비스워커가 켜진 경우에도 같은 지연 요청 조건을 별도로 확인했다.

- 지도 코드와 마을 그림을 각각 차단했다. 차단을 풀면 다시 열기로 지도가 복구됐고, 차단을 유지해도 첫 활동에서 시간 슬라이더로 여덟 관측 기록을 모아 완료했다. 새로고침 뒤에도 기록이 남았다.
- 응답 자체를 보류했을 때도 지도 코드 약 10.4초, 그림 약 20.4초 뒤에 첫 활동을 열 수 있었다. 지도를 기다리다가 홈으로 나가면 늦게 온 응답이 홈을 덮지 않았다.
- 도시 운영 미션을 지도·활동 코드 요청 없이 열고 닫은 뒤 키보드 초점이 버튼으로 돌아왔다.
- 서비스워커 설치 뒤에도 미진입 화면을 받지 않았다. 전체 자료를 준비한 뒤 오프라인에서 지도·활동·도시 운영 미션을 확인했고, 기존 배포 검사에서도 오프라인 개념 영상·구간 이동·힌트가 통과했다.
- 정적 배포 빌드와 단위 테스트 59개가 통과했다. 실제 흐름대로 시설 사이와 최종 보고 직전에 지도를 거치도록 조정한 브라우저 검사에서 전체 활동 10개·조작 72건, 인증서 다운로드와 새로고침을 확인했다.
- 운영 주소는 유지했고 배포하지 않았다.
