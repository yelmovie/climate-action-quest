# 0. 이번 v2 심화 설계의 목적

기존 「기후 미래 작전실」의 장점인

- 기후 신호 관측
- 증거 기반 판단
- 인간 활동 스캐너
- 관련성 추적망
- 3D 해수면 미래 실험
- 영향 연쇄 분석
- 하루 선택 시뮬레이션
- 3D 미래도시 설계
- 기후 스트레스 테스트

를 그대로 유지한다.

다만 10개 화면이 **각자 잘 만든 활동 10개**로 흩어져 보이지 않도록, 전체를 하나의 사건을 해결하는 **Quest → Evidence → World Change → Final Report → Final Mission** 구조로 통합한다.

학생의 경험은 다음과 같아야 한다.

> “기후변화 문제를 몇 개 풀었다.”

가 아니라

> **“도시의 이상 신호를 조사하고, 원인과 영향을 밝혀내고, 내가 설계한 대응 도시를 직접 시험해서 작전실을 정상화했다.”**

# 1. 기존 설계 진단

## 1-1. 현재 설계의 강점 — 유지

### A. 교육과정 흐름이 좋다

핵심 성취기준이 5개 Mission에 자연스럽게 분산되어 있다.

- **[4과16-01]** 기후변화 현상 사례 + 인간 활동과의 관련성
- **[4과16-02]** 생활·환경 영향
- **[4과16-03]** 대응 방법 조사 + 생활 속 실천

개념을 외우는 순서가 아니라

**관찰 → 근거 판단 → 관계 추론 → 영향 예측 → 대응 설계**

로 이어지는 점을 유지한다.

### B. 태블릿을 쓸 이유가 분명한 핵심 기능이 이미 있다

특히 다음 세 기능은 프로젝트의 킬러 기능으로 유지한다.

1. **3D 해수면 미래 실험**
   - 3D 도시 회전
   - 예상 침수 영역 직접 표시
   - 수위 단계 조절
   - 예상/결과 겹쳐 비교
   - 재실험

2. **3D 미래도시 설계**
   - 위험도 자료 읽기
   - 제한 자원
   - 대응 시설 직접 배치
   - 공간에 따른 효과 변화

3. **기후 스트레스 테스트**
   - 내가 만든 도시를 그대로 시험
   - 취약 지역 확인
   - 설계 수정
   - 같은 조건 재시험
   - Before/After 비교

### C. 10개 화면의 조작이 서로 다르다

- Scan
- Wipe Compare
- Evidence Connect
- 2.5D Explore
- Graph Link
- 3D Rotate
- Freehand Prediction
- Slider
- Chain Simulation
- Branching Choice
- A/B Compare
- Object Placement
- Stress Simulation
- Redesign

동일한 Drag UI를 복제하지 않는다는 점을 유지한다.

## 1-2. 게임성이 약해질 수 있는 부분 — 개선

### 문제 1. Stage 완료가 “활동 하나 끝”으로 보일 가능성

기존 설계만으로도 활동은 좋지만, Stage 간 연결이 약하면 학생은

> “다음 문제”

로 인식할 수 있다.

### 개선

각 Mission이 끝날 때 **연구 결과물(Evidence)** 을 획득하고, 그 결과물이 실제 작전실/도시 상태를 바꾸게 한다.

예:

- Mission 1 → `기후 신호 관측 기록`
- Mission 2 → `인간 활동 관련성 지도`
- Mission 3 → `미래 영향 예측 보고서`
- Mission 4 → `생활 대응 실천안`
- Mission 5 → `기후 대응 도시 설계도`

---

### 문제 2. 샘플 UI가 잘못 구현되면 학습지형으로 변할 수 있음

샘플페이지는 시각적으로는 매우 좋지만, 실제 개발에서 카드와 빈칸을 그대로 고정하면 다시 “화려한 학습지”가 될 위험이 있다.

### 개선

카드는 **결과 표시용 UI**이고, 핵심 학습은 반드시 학생의 이전 행동/데이터와 연결한다.

예:

- P3 증거카드 → P2에서 학생이 실제로 획득한 것만 표시
- P5 관계 노드 → P4에서 스캔한 활동만 입력 가능
- P7 영향 체인 → P6 실험 기록을 일부 재사용
- P10 테스트 → P9에서 학생이 직접 배치한 도시 상태 사용

즉,

> **화면마다 새 문제를 주는 구조가 아니라 이전 화면에서 만든 상태를 다음 화면이 이어받는다.**

---

### 문제 3. 샘플 이미지 안 일부 표현은 최종 과학 로직에서 보정 필요

샘플 이미지는 **UI·레이아웃·상호작용 컨셉 시안**이며, 이미지 안 문구와 수치가 최종 과학 데이터는 아니다.

#### 반드시 보정할 것

1. **Stage 4 지표**
   - 샘플 이미지처럼 자동차/도보 선택 결과가 곧바로 `폭염·홍수·가뭄 위험`을 높이거나 낮춘다고 표현하지 않는다.
   - 최종 지표는 원래 설계대로:
     - `기후 부담`
     - `생활 만족`
     - `사용 자원`
   - 모두 **게임 내 상대 비교 지표**로 표시한다.

2. **Stage 5 테스트 수치**
   - 샘플 이미지의 `36.8℃`, `시간당 80 mm`, `88%` 같은 값은 **디자인 자리표시자**로 본다.
   - 실제 개발에서는 근거 없는 구체 수치를 사용하지 않는다.
   - 기본은 `낮음 / 보통 / 높음`, `영향 단계 0~3` 등 상대값을 사용한다.
   - 실제 수치를 사용할 경우 출처와 기준 날짜를 데이터에 함께 저장한다.

3. **Stage 2 관련성 추적망**
   - 4학년 핵심은 인간 활동과 기후변화의 **관련성을 이해하고 토의하는 것**이다.
   - 지나치게 세부적인 중등 수준 메커니즘 설명은 핵심 미션에서 제외한다.
   - 기본 노드는 `활동 → 에너지/자원 사용 또는 숲 변화 → 기후변화와의 관련성` 수준으로 제한한다.

4. **실제 도시/미래 피해**
   - 특정 실제 도시의 미래 침수 확정 지도로 표현하지 않는다.
   - P6·P9·P10은 모두 **가상 교육용 도시 모형**이다.

# 2. 단원 메인 퀘스트

## 사건

「기후 미래 작전실」의 도시 예측 시스템이 서로 다른 이상 신호를 동시에 감지했다.

그런데 관측 자료, 인간 활동 자료, 미래 영향 자료, 대응 데이터가 서로 연결되지 않아 **기후 코어가 5개 구역으로 분리**되었다.

작전실은 현재

- 어떤 신호가 중요한지,
- 인간 활동과 어떻게 관련되는지,
- 미래에 어떤 영향을 줄 수 있는지,
- 어떤 대응이 필요한지

판단하지 못한다.

---

## NPC 의뢰

### NPC 1 — 잎새 다람쥐 연구원

**역할:** 관측·기록·Evidence 보관 담당

- 관측 미션 의뢰
- 조사 기록 관리
- Evidence Research Kit 담당
- Final Report에서 학생 탐구 기록 정리

성격:
- 꼼꼼함
- 기록을 중요하게 생각함
- 학생에게 답을 알려주기보다 “어떤 자료를 더 봐야 할까?”라고 질문

---

### NPC 2 — 물방울 수달 연구원

**역할:** 실험·검증·시뮬레이션 담당

- P2 스캐닝 보조
- P6 해수면 실험 안내
- P9 도시 설계 테스트
- P10 스트레스 테스트 결과 해석

성격:
- 실험적
- 한 번 실패해도 다시 해보는 것을 긍정
- “예상과 다르네. 조건을 하나 바꿔 다시 시험해 보자.”라는 역할

### 캐릭터 원칙

두 캐릭터는 **각 화면의 장식 캐릭터가 아니라 역할을 가진 NPC**로만 사용한다.

- 부엉이 사용 금지
- 로봇 사용 금지
- 화면마다 두 캐릭터를 반드시 모두 넣지 않음
- 필요한 화면에 필요한 NPC만 노출
- 캐릭터가 설명문을 대신 읽어주는 구조 금지

---

## 최종 목표

5개의 Mission에서 얻은 연구 결과를 기후 코어에 다시 연결하여

> **“도시의 문제를 관찰하고 → 영향을 예측하고 → 대응 도시를 설계하고 → 같은 조건으로 다시 검증”**

한다.

마지막에는 학생이 Final Report를 제출하고, 자신이 설계한 대응 계획을 실제 도시 시뮬레이터에 적용해 **기후 코어를 직접 재가동**한다.

# 4. Mission 1~5 심화 설계표

## MISSION 01 — 이상 신호의 증거

| 항목 | 내용 |
|---|---|
| **학습목표** | 기후변화 현상의 예를 관찰하고 여러 증거를 바탕으로 판단한다. |
| **퀘스트 상황** | 관측 시스템이 서로 다른 이상 신호를 감지했지만 라벨 데이터가 손상됨 |
| **학생 핵심 행동** | 여러 지점 관찰 → 자료 2개 이상 확보 → 현상 판단 |
| **주요 상호작용** | 3D 회전, Tap, Scan, Zoom, Before/After Wipe, Evidence Drag |
| **Micro Loop** | 지점 선택 → 스캔 → 자료 변화 확인 → 증거 저장 → 비교 → 부족하면 다시 조사 |
| **실패/재시도** | 근거 부족 시 현상 오답 대신 “다른 자료를 더 확인”하도록 되돌림 |
| **과학적 피드백** | 기온·강수·토양·수위·눈 등 관측 자료 자체가 피드백 |
| **Evidence** | 기후 신호 관측 기록 |
| **World Change** | 관측 레이더 복구, 지도 신호가 미확인 점멸 → 분류된 관측점으로 변화 |
| **유지** | 도시 스캔, 증거 2개 이상, 비교 |
| **개선** | 단순 현상 선택이 아닌 “내가 모은 증거”만 판정에 사용 |

---

## MISSION 02 — 인간 활동의 흔적

| 항목 | 내용 |
|---|---|
| **학습목표** | 인간 활동이 기후변화와 관련되어 있음을 조사하고 관계로 표현한다. |
| **퀘스트 상황** | 도시 활동 데이터 레이어가 사라져 어떤 활동이 기후 분석과 관련되는지 확인 불가 |
| **학생 핵심 행동** | 도시 탐색 → 활동 스캔 → 데이터 오버레이 확인 → 관계망 구성 |
| **주요 상호작용** | Pan, Scanner Drag, Layer On/Off, Node Link, Graph Validate |
| **Micro Loop** | 장소 조사 → 숨은 자원/에너지 흐름 확인 → 증거 저장 → 관계 연결 → 검증 → 잘못된 edge 수정 |
| **실패/재시도** | 직접 연결만 하면 중간 근거 부족으로 검증되지 않음 |
| **과학적 피드백** | 에너지·교통·자원·숲 변화 레이어가 시각적 반응 |
| **Evidence** | 인간 활동 관련성 지도 |
| **World Change** | 도시 지도에 활동 데이터 레이어가 복구되고 구역별 흐름이 보이기 시작 |
| **유지** | 학교·주택·교통·생산·숲 탐색 |
| **개선** | “나쁜 행동 찾기” 대신 관련성 네트워크를 학생이 구성 |

---

## MISSION 03 — 미래 영향 실험

| 항목 | 내용 |
|---|---|
| **학습목표** | 기후변화가 생활과 환경에 미칠 수 있는 영향을 예측·설명한다. |
| **퀘스트 상황** | 미래 시뮬레이터가 작동하지만 예측 데이터가 없어 결과 검증 불가 |
| **학생 핵심 행동** | 3D 지형 관찰 → 침수 예상 표시 → 수위 조작 → 결과 비교 → 영향 체인 구성 |
